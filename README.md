> ### Welcome to pysubgroup v2!

This repository and the `pysubgroup` package on PyPI now hold pysubgroup v2,
a complete rewrite that replaces the previous version. The old version
remains available in the git branch `legacy`. What is new:

- **Faster.** In our benchmarks more than ten times faster than the old pysubgroup, thanks to batched evaluation of candidates on packed bitsets and optional numba kernels. It also finishes tasks where the old version times out.
- **More reliable.** More than 1,900 tests, parity checks against the old pysubgroup (identical top-10 qualities in every benchmark task both versions finished), deterministic tie-breaking, and clearly defined handling of missing values.
- **Still easy to use.** An intuitive API in which a search takes a few lines, as before: a target, a search space, a quality function, and an algorithm.
- **Modern API.** Targets fitted in the scikit-learn style, immutable `Condition` and `Rule` objects, results as plain `(quality, rule)` pairs, NumPy 2 and Python 3.11 to 3.14.
- **Comprehensive.** Search algorithms (DFS, best-first, OPUS, DpSubgroup, Apriori, SD-Map, SD-Map*, GP-growth, NumBSD, VLSD, beam search, DSSD, and generalization-aware search) for binary, numeric, multiclass, nominal, and vector-valued targets, plus exceptional model mining, significance filtering, and visualizations. Each algorithm is implemented from its publication.

> ⚠️ pysubgroup v2 was essentially rewritten from scratch, with most of the code actually generated by AI tools (at the time of writing, primarily Claude Opus and GPT-5.6 Sol), while design decisions and high-level code reviews were handled by humans.
>
> While this might not sit well with purists, it has enabled us to implement more features, produce more efficient, robust, and thoroughly tested code, and focus our attention on the most scientifically interesting decisions—all while aiming for production-ready (we hope!) reliability.
> In fact, I personally feel much more confident in the current version of pysubgroup than in the previous version, which I wrote manually over the years. This is also reflected in the version jump from 0.9 to 2.0.
>
> Note that the old, human-written version of pysubgroup is still available in the `legacy` branch.

## A first example

Which groups of people are most likely to earn more than 50K a year?

```python
from sklearn.datasets import fetch_openml
import pysubgroup as sd

data = fetch_openml("adult", version=2, as_frame=True).frame.drop(columns="fnlwgt")

target = sd.BinaryTarget().fit(data, "class", ">50K")
conditions = sd.generate_conditions(data.drop(columns="class"))
task = sd.SubgroupDiscoveryTask(
    data, target, conditions, sd.WRAccQF(), result_set_size=5, depth=2
)
result = sd.DFS().execute(task)
print(sd.to_dataframe(result, data, target))
```

## Subgroup Discovery

Subgroup Discovery is a well-established data mining technique that allows you to identify patterns in your data.
More precisely, the goal of subgroup discovery is to identify descriptions of data subsets that show an interesting distribution with respect to a pre-specified target concept.
For example, given a dataset of patients in a hospital, we could be interested in subgroups of patients for which a certain treatment X was successful.
One example result could then be stated as:

_"While in general the operation is successful in only 60% of the cases, for the subgroup
of female patients under 50 that also have been treated with drug D, the success rate was 82%."_

Here, a variable _operation success_ is the target concept, and the identified subgroup has the interpretable description _female=True AND age<50 AND drug_D=True_. We call these single selection expressions (such as _female=True_) _conditions_.
The interesting behavior for this subgroup is that the distribution of the target concept differs significantly from the distribution in the overall dataset.
A discovered subgroup could also be seen as a rule:
```
female=True AND age<50 AND drug_D=True ==> Operation_outcome=SUCCESS
```
Computationally, subgroup discovery is challenging since a large number of such conjunctive subgroup descriptions have to be considered. Of course, finding computable criteria for which subgroups are likely to interest a user is also an eternal struggle.
Therefore, a lot of literature has been devoted to the topic of subgroup discovery (including some of my own work). Overviews of the topic are, for example:

## How to use

A search has four ingredients: a **target** (the property of interest), a
**search space** (a list of conditions), a **quality function**, and an
**algorithm**. They are combined in a `SubgroupDiscoveryTask`:

```python
import pysubgroup as sd

target = sd.BinaryTarget().fit(data, "class", ">50K")
conditions = sd.generate_conditions(data.drop(columns="class"))
task = sd.SubgroupDiscoveryTask(
    data,
    target,
    conditions,
    sd.WRAccQF(),
    result_set_size=10,   # number of subgroups returned
    depth=2,              # maximum number of conditions per subgroup
)
result = sd.DFS().execute(task)
```

The result is a list of `(quality, rule)` pairs, best first:

```python
for quality, rule in result:
    print(f"{quality:.4f}  {rule}")
# 0.0948  [marital-status=Married-civ-spouse]
# 0.0892  [marital-status=Married-civ-spouse ∧ native-country=United-States]
# ...
```

`sd.to_dataframe(result, data, target)` turns it into a table with sizes and
target statistics, and `sd.subgroup_data(result[0], data)` returns the rows
that a subgroup covers.

### Numeric targets

For a numeric target, use `NumericTarget` with a numeric quality function.
Filters such as a minimum subgroup size restrict the results:

```python
target = sd.NumericTarget().fit(data, "hours-per-week")
conditions = sd.generate_conditions(data.drop(columns=["class", "hours-per-week"]))
task = sd.SubgroupDiscoveryTask(
    data, target, conditions, sd.StandardQFNumeric(a=0.5),
    result_set_size=5, depth=2, filters=[sd.MinSizeFilter(100)],
)
result = sd.DFS().execute(task)
print(sd.to_dataframe(result, data, target))
```

### Other algorithms

All exhaustive algorithms return the same subgroups; heuristic ones trade
completeness for speed or diversity. Swap the algorithm without changing the
task:

```python
sd.BestFirstSearch().execute(task)
sd.BeamSearch(beam_width=10).execute(task)   # heuristic
sd.NumBSD().execute(task)                    # exhaustive, for numeric targets
sd.DSSD().execute(task)                      # diverse subgroup sets
```

### Your own search space

`generate_conditions` returns an ordinary list of conditions; extend or replace
it with your own:

```python
from pysubgroup import Condition

conditions = sd.generate_conditions(data.drop(columns="class"), n_bins=5)
conditions.append(Condition("age", "gt", 35))
conditions.append(Condition("age", "interval", lower=20, upper=30))  # (20, 30]
```

## Key classes

- `Condition`: an atomic condition such as `age > 35` or `sex = Female`.
- `Rule`: a conjunction of conditions, the description of a subgroup.
- Targets (`BinaryTarget`, `NumericTarget`, `MulticlassTarget`, ...): fitted on
  the data; they hold the target statistics.
- Quality functions (`WRAccQF`, `StandardQF`, `StandardQFNumeric`, ...): score
  a subgroup and, for exhaustive searches, bound the quality of its
  refinements (optimistic estimates).
- `SubgroupDiscoveryTask`: what to search for; an algorithm's `execute` runs it.
